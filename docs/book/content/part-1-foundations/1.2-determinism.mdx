In the previous chapter we said the worldgen pipeline's job is to turn a `(seed, ChunkCoord)` into a `DenseChunk`. The word *"deterministic"* doing all the heavy lifting in that sentence is what makes the engine work. Every roll — *which plate is at this column, where do trees go in this cell, does this cave chamber roll a sinkhole entrance* — has to give the same answer every time, on every machine, with no per-process state.

The trick is to never use a stateful random number generator. Instead, every random roll is a pure function of three things: the world seed, some integer coordinates, and a salt integer that distinguishes one kind of roll from another at the same location. We call that function the **hash mixer**.

## The picture

A hash mixer takes a small bundle of integers and returns a single integer that *looks* random but is fully determined by its inputs.

```
mix(seed: u64, words: &[i32]) -> u64
```

`mix(42, &[10, 20])` always returns the same `u64`. But `mix(42, &[10, 20])` and `mix(42, &[20, 10])` return very different `u64`s — the function is sensitive to argument order, which lets the position of an integer carry meaning (e.g., "this is an X coordinate; this is the salt that says I'm rolling jitter-x").

From a `u64`, you can derive any kind of randomness you need:

- A `[0, 1)` float: take the top 24 bits, divide by $2^{24}$.
- A roll in `[lo, hi)`: scale that float.
- A "yes with probability p" decision: compare the float to `p`.

Every random thing the engine does — every one — routes through this same function. No `rand::thread_rng()`, no `RandomState`, no `Instant::now()` mixed into a seed somewhere.

## Build it

A solid 64-bit mixer is about 15 lines of code. Here is the real implementation from `src/worldgen/hash.rs`:

```rust
pub fn mix(seed: u64, words: &[i32]) -> u64 {
    let mut h = seed.wrapping_mul(0x9E37_79B9_7F4A_7C15);
    for (i, w) in words.iter().enumerate() {
        // Per-position multipliers — large primes with good
        // bit-distribution — keep mix(s, &[a, b]) distinct from
        // mix(s, &[b, a]).
        let mult = [
            0xC2B2_AE3D_27D4_EB4F_u64,
            0x1656_67B1_9E37_79F9,
            0xCC9E_2D51_1B87_3593,
            0x85EB_CA6B_27D4_EB4F,
            0xC2B2_AE3D_85EB_CA6B,
        ][i % 5];
        h ^= (*w as i64 as u64).wrapping_mul(mult);
        h = h.rotate_left(((i as u32) % 5) * 4 + 13);
    }
    // Finaliser — full avalanche.
    h ^= h >> 33;
    h = h.wrapping_mul(0xFF51_AFD7_ED55_8CCD);
    h ^= h >> 33;
    h = h.wrapping_mul(0xC4CE_B9FE_1A85_EC53);
    h ^= h >> 33;
    h
}
```

Each word gets a different multiplier from the 5-element table (rotating with `i % 5`), then a different rotation amount. That combination is what makes the mixer order-sensitive: rearranging the words array routes each word through a different multiplier and rotation slot.

The three-step finaliser at the bottom is the **avalanche** step. Without it, flipping one bit of input changes only roughly one bit of output on average — which means correlated inputs (adjacent coords, similar seeds) produce correlated outputs, and the world would have visible patterns at small scales. With the finaliser, flipping any input bit flips roughly half the output bits — the gold standard for a non-cryptographic hash.

From there, the convenience wrappers follow naturally:

```rust
// Returns mix(...) cast to u32.
pub fn mix_u32(seed: u64, words: &[i32]) -> u32 {
    mix(seed, words) as u32
}

// Returns a float in [0, 1).
pub fn mix_unit(seed: u64, words: &[i32]) -> f32 {
    // Top 24 bits — plenty of precision for any spawn-rate roll.
    ((mix(seed, words) >> 40) as f32) / ((1u64 << 24) as f32)
}

// Returns a float in [lo, hi).
pub fn mix_range(seed: u64, words: &[i32], lo: f32, hi: f32) -> f32 {
    lo + mix_unit(seed, words) * (hi - lo)
}
```

Top bits, not low bits — the avalanche step distributes bias more evenly at the high end. And $2^{24}$ is what `f32` mantissa precision supports cleanly, so you never lose resolution from the truncation.

## In the engine

Look at a typical call site — biome-edge Voronoi jitter in `src/worldgen/climate.rs`:

```rust
// src/worldgen/climate.rs — two-axis jitter on quartic-cell corners
// so adjacent biome cells produce squiggly borders.
let jx = crate::worldgen::hash::mix_unit(seed, &[cqx, cqy, cqz, 0]) as f64;
let jz = crate::worldgen::hash::mix_unit(seed, &[cqx, cqy, cqz, 1]) as f64;
let jitter_x = jx * 0.9 - 0.45;
let jitter_z = jz * 0.9 - 0.45;
```

Two rolls — `jitter_x` and `jitter_z` — at the same cell. Each gets a different *salt* as the last word (`0` vs `1`), which means the two rolls are uncorrelated even though they share `(seed, cqx, cqy, cqz)`. If both rolls used the same salt they would produce identical values, and biome edges would only ever jitter diagonally (along $x = z$). The integer salt is what buys independence between rolls that share the same coordinates.

The same pattern appears in `src/worldgen/aquifer.rs`, which needs three independent jitter values to place an aquifer cell center:

```rust
// src/worldgen/aquifer.rs — three-axis jitter, one salt per axis.
let jx = (hash::mix(self.seed, &[cx, cy, cz, 0]) as u32) % cell_width;
let jy = (hash::mix(self.seed, &[cx, cy, cz, 1]) as u32) % cell_height;
let jz = (hash::mix(self.seed, &[cx, cy, cz, 2]) as u32) % cell_depth;
```

Salts `0`, `1`, `2` — one per axis. Three uncorrelated rolls, one `mix` call each. No RNG state to thread through.

And in `src/worldgen/surface.rs`, a surface decoration rule checks whether a plant spawns at a given column:

```rust
let roll = hash::mix_unit(ctx.seed, &[ctx.wx, ctx.wz, 71]);
roll < probability
```

The literal `71` is the salt for this particular rule. A different decoration rule at the same column uses a different literal, giving it an independent roll.

This is the recurring pattern throughout worldgen: wherever you see `hash::mix*(seed, &[...coords..., salt])`, the trailing integer salt is buying independence between rolls that share the same coordinates.

## What you can now do in the code

You can read:

- `src/worldgen/hash.rs` — every mixer variant in the engine.
- Every `hash::mix*` call site in `src/worldgen/`. The trailing integer in the `words` slice is the salt; its value is arbitrary but unique per roll at that location.

When a future chapter says "the engine rolls a value here," you'll know it means `mix_unit(seed, &[coord, salt])`, and you can find the exact salt literal at that call site to understand what it controls.
